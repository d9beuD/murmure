# Release 0.1.0 Checklist

## Before signing

- [ ] `swift build -Xswiftc -warnings-as-errors`
- [ ] `swift test -Xswiftc -warnings-as-errors`
- [ ] Confirm that no secrets, audio files, or logs are tracked.
- [ ] Check the logs with an endpoint that returns an error message containing
      user text: the text must not appear.
- [ ] Test Microphone permission when denied, then allowed.
- [ ] Test Accessibility permission when denied, then allowed.
- [ ] Test Notes, TextEdit, Safari, Mail, Terminal, Xcode, and a password field
      in both clipboard and automatic-insertion modes.
- [ ] Test a remote HTTPS endpoint, a loopback HTTP endpoint, and a network
      failure during STT and then TTT.

## Signing and notarization

- [ ] Install a stable Xcode version compatible with macOS 26.
- [ ] Configure a `Developer ID Application` identity in Keychain.
- [ ] Set the six signing and notarization variables below, then run
      `ENTREVOIX_VERSION=0.1.0 ./Scripts/release.sh`.
- [ ] Check the final DMG with `spctl --assess --type open --verbose`.
- [ ] Publish the DMG, the release notes, and the MIT License on GitHub Releases.
- [ ] Confirm that GitHub displays a SHA-256 digest for the uploaded DMG.

## GitHub Release workflow

Run the **Release** workflow manually from the *Actions* tab. It asks for a
version, creates the `v<version>` tag, builds a signed and notarized DMG,
attaches the DMG to the release, and publishes the notes generated by GitHub.
GitHub computes and displays the DMG's SHA-256 digest automatically.

Signing and notarization are mandatory for a GitHub release: the workflow fails
explicitly if any required secret is missing.

Configure these repository secrets:

- `DEVELOPER_ID_CERTIFICATE_BASE64`: the Developer ID Application certificate
  in Base64-encoded `.p12` format;
- `DEVELOPER_ID_CERTIFICATE_PASSWORD`: the password for that `.p12` file;
- `BUILD_KEYCHAIN_PASSWORD`: the password for the temporary CI keychain;
- `APP_STORE_CONNECT_KEY_BASE64`: the Base64-encoded App Store Connect Team API
  `.p8` key;
- `APP_STORE_CONNECT_KEY_ID` and `APP_STORE_CONNECT_ISSUER_ID`: the identifiers
  for that key.

The script reconstructs the `.p8` key in a temporary directory, calls
`xcrun notarytool submit --key --key-id --issuer` directly, then deletes the
temporary files and CI keychain. It uses no Apple ID, app-specific password,
`notarytool` profile, or `altool`.
